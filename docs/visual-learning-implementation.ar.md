# تجربة فهم RAG بالرسم — ٢٢ أكتوبر ٢٠٢٦

اتنفّذت أول مرحلة محلية من [الخطة البصرية](specs/learning-visuals.md) على
`codex/visual-learning`: شرح بالمصري لورقة `2005.11401v4`، مع رسم لطريقة
التدريب ورسم للاستخدام. الشرح والمراجع مُعدّين من المصدر داخل المشروع؛
دي مش نتيجة توليد جديدة من موديل، ولا تقييم تعليمي مستقل.

## جرّبها على الكمبيوتر

من جذر المشروع، باستخدام بيئة Python الموجودة:

```powershell
.venv-win/Scripts/python.exe -m src.commands.study_visual --output data/study/my-rag-visual-demo
```

افتح `index.html` داخل المجلد الناتج في Chrome أو Edge. اختار اسم مجلد جديد
كل مرة؛ الأمر بيرفض الكتابة فوق نتيجة موجودة. النسخة الجاهزة للمراجعة على
جهاز التطوير موجودة في `data/study/visual-learning-demo-20261022-v2/index.html`.
المخرجات دي متجاهلة في Git؛ أي شخص يقدر يعيد إنشاءها بالأمر أعلاه.

التجربة دي مش محتاجة Docker أو تشغيل API أو توكن أو تحميل أوزان موديل.
التنقل وفحص المكونات وفتح المقتطفات محليين؛ فتح رابط الورقة الأصلية بإيدك
بيفتح arXiv. الصور وروابط التحميل موجودة جنب صفحة الشرح.

## الموجود في التجربة

- التحويل بين التدريب والاستخدام، والتنقل بين أربع خطوات لكل مرحلة.
- تمييز المكونات والأسهم المرتبطة بالخطوة، وفحص دور المكوّن بالماوس أو الكيبورد.
- الدليل الأصلي بمقتطف قصير ورقم صفحة/بلوك، ورابط الصفحة للسياق الكامل.
- شرح عربي RTL، ومصطلحات إنجليزية معزولة باتجاه LTR، ونسخ للنص المنطقي الأصلي.
- كل الشرح كنص قابل للقراءة، مع استمرار التنقل والمراجع لو الرسم اختفى.
- SVG وPNG للتصدير، وملف spec وmanifest فيه بصمات ملفات النتيجة.

ألوان وأنواع الأسهم ليها معاني ثابتة: داتا، تجهيز مسبق، وتحديث أوزان.
الواجهة ما بتعكسش اتجاه الرسم العلمي. الـquery encoder والـBART generator
بيتحدّثوا في التدريب؛ الـdocument encoder والفهرس ثابتين في الإعداد المراجع.
الرسم للمكونات والتحديثات، مش تفصيل كامل لكل خطوات beam decoding.

## حدود التنفيذ وقراراته

اخترنا بيانات مراجعة وقالب رسم ثابت عشان نختبر الفهم والقراءة قبل إضافة
موديل تخطيط. الـspec بحد أقصى ١٦ KiB و١٢ مكوّن و٢٤ سهم و٨ خطوات؛ بيرفض
المصدر أو النسخة أو البصمة المختلفة، والمراجع غير المعروفة، وتحديث الأجزاء
الثابتة. كمان بيرفض أي صياغة أو تركيب خارج المحتوى المراجع. قبول fact ID
لوحده مش إثبات لصحة كلام جديد؛ دعم ورق جديد محتاج مسار تخطيط ومراجعة منفصل.

العرض HTML/CSS/JS مكتوب في التطبيق، والـSVG بيتبني من عناصر محددة. مفيش
كود أو مسارات ملفات من الموديل، ولا موارد خارجية لازمة لعرض الصفحة.
سياسة CSP بتمنع اتصالات الشبكة، وبتسمح بس بكود العرض الثابت ببصمته.

الـPNG الحالي بيستخدم worker Windows/GDI ثابت، بخط يدعم تشكيل العربي وقياس
النص كاملًا بالبكسل قبل الرسم. مدته محدودة، وبيوصله بيانات المشهد بس من غير
بيئة أسرار التطبيق. لو الذاكرة الحرة أقل من ٦٠٠ MiB، أو قياسها غير متاح، أو
التشكيل/الرسم فشل، التصدير يحتفظ بالـSVG والنص. على الأنظمة الأخرى PNG لسه
غير متاح في المسار الجديد. ده ما بيغيرش حدود ذاكرة البوت أو استدعاءات HF،
وما بيضيفش متصفح أو موديل لتشغيله العادي.

فشل الكتابة بيرجع خطأ محدود ويحاول إزالة الملفات اللي أنشأها فقط. لو النظام
منع التنظيف ممكن يفضل مجلد جزئي؛ استخدم مجلد جديد بعد حل مشكلة التخزين.

## دليل التحقق

٥٤ اختبارًا مركزًا نجحوا، مع Ruff وmypy على ١٦١ ملف مصدر. الاختبارات بتغطي
الهوية والحدود والمراجع والصياغة، النص المختلط، الرسم، فشل الذاكرة، منع
الكتابة فوق الملفات، وفشل الكتابة والتنظيف. مراجعة المصدر مرتبطة ببصمة PDF
ومواضع محددة؛ راجع [الـfixture وحدوده](../evaluation/visual_learning/README.md).

اختبارات المشروع العامة: ١٥٣٩ اختبار unit/API نجحوا في ٨٣٣٫٦٦ ثانية، مع
تحذيرَي deprecation من Typer/Click. اختبار الرسم الحقيقي مستقل عن تذبذب RAM
التطبيقات الأخرى؛ حالات رفض الذاكرة متغطية بشكل منفصل، وآخر تشغيل له نجح
بـ١٢ اختبارًا. كمان تصدير الشرح من `git archive` نظيف نجح بنفس بيئة Python،
من غير `.env` أو PDF متجاهل أو إعدادات حساب، وطلع الرسمين SVG وPNG.

اختبار فعلي في Chrome 155 بملف شخصي مؤقت مستقل أثبت:

- تنقل وفحص مكونات ومراجع، وأسماء متاحة للأزرار، والحفاظ على تركيز الكيبورد.
- عرض النص عند ٣٢٠/٧٦٨/١٠٢٤/١٤٠٠ بكسل، وتكبير النص ٢٠٠٪ مع تعديلات المسافات.
- ١٢ حالة قراءة مشتركة: ١١ حالة معروضة وحالة تحكم اتجاه خبيث مرفوضة.
- تطابق نص النسخ والاختيار في حقل احتياطي عند منع صلاحية Clipboard.
- استمرار الخطوات والمصادر بدون SVG؛ وعند فساد البيانات يظهر كل النص والدليل.
- صفر أخطاء/تحذيرات console وصفر طلبات HTTP/HTTPS من الصفحة.
- زمن p95 لتنقل ١٠٠ خطوة: ٣٦٫٨ ms في التشغيل المسجّل، مش ضمان لكل جهاز.

اتراجعت صور SVG وPNG الفعلية للتدريب والاستخدام. حالات القراءة الاثناشر
اتجرّبت في HTML؛ رسم SVG/PNG الحالي بيقبل تسميات الـfixture المحددة فقط،
مش مصطلحات أو معادلات جديدة بلا اختبار. دي مش شهادة WCAG أو اختبار Telegram.
المراجع الإنجليزية قصيرة للوصول للمكان؛ الصفحة الأصلية لازمة للسياق.

لإعادة اختبار المتصفح، مع Chrome أو Edge وبيئة التطوير الموجودة:

```powershell
.venv-win/Scripts/python.exe -m tests.browser.visual_viewer_cdp --viewer data/study/my-rag-visual-demo/index.html --output tests/test_output/my-rag-browser-check
```

مش متاح Chrome DevTools MCP في البيئة دي، فالأداة بتستخدم CDP محلي على
loopback بملف مؤقت، وتقفل المتصفح اللي أنشأته فقط. مفيش وصول لبروفايلك أو
قراءة/تغيير Clipboard النظام. لقطات الاختبار صور viewport فعلية؛ تصوير Chrome
155 خارج الـviewport كان بيزحزح بعض صفحات RTL، فاتراجع كل قسم بصورة منفصلة.
دليل الجهاز متجاهل في `tests/test_output/visual-browser-20261022-accepted/`.

## الخطوة التالية

أول دفعة موثوقية (٣ نوفمبر ٢٠٢٦) اتنفّذت أوفلاين:

- [حالات الأخطاء العلمية](../evaluation/paper_learning/README.md): ١٠ أخطاء حرجة
  و٤ أقسام صحيحة من حقائق RAG المراجعة. التحقق الأوفلاين بيوقف ٣ بس؛ الباقي
  بيعتمد على مراجعة الموديل، والاختبارات بتثبت إنها بتوصلها بالمصدر كامل.
  اتصلّح خطأ كان بيعدّي رقم مخترع لو لازق في "و" أو "بـ" أو "لـ".
- تشخيص `/deep`: كل فشل بيتسجّل بمرحلة محددة (من الإعدادات لحد خروج العملية)
  وبيظهر للمالك بأسماء آمنة. سبب الفشل القديم لسه مجهول.
- [قياس الذاكرة](resource-profile-20261103.md): أكبر استهلاك هو استيراد الـAPI
  (~١٢٩ MiB)، وworker الـPNG أكبر عملية في الرسم. الذاكرة الحرة على الجهاز
  (~١٫٧ GiB من ١٦) هي الخطر الحقيقي، مش التطبيق.

باقي من الأساس: حالة إشارات المعادلات، الـrubric، وحجز الـholdout، وتحسين
مقاس (P2). بعدها ربط هوية المصدر بمكتبة الدراسة ومكان التوقف. بعدها حفظ نسخ الرسوم لكل مستخدم، وأفعال API
محمية، وتوصيلها بـTelegram. توليد رسم لأي ورقة، وOCR، وتفسير المعادلات،
والاستضافة وNotion ليهم مهام واختبارات مستقلة في [القائمة الكاملة](../tasks/todo.md).

التنفيذ ده استهلك صفر inference، وما شغّلش موديل جديد أو بعت رسالة Telegram
أو أعاد تشغيل البوت. فشل `/deep` القديم لسه غير محلول؛ نجاح العرض المحلي
ما يثبتش نجاح المسار ده. ميزانياته القديمة وطلب تشخيصه المعلّق منفصلين.
