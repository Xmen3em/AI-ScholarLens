Ownership: PostgreSQL owns the canonical paper record. OpenSearch is a rebuildable retrieval projection. Airflow moves data between sources and stores. FastAPI orchestrates retrieval, evidence selection, validation, and cited responses.

Input

Eight arXiv AI categories

cs.AI, cs.LG, cs.CL, cs.CV, cs.RO, cs.MA, cs.NE, and stat.ML. Cross-listed papers qualify when any category is allowlisted.

Output

Ranked papers and cited excerpts

Clients can browse metadata, search grouped passages, and request up to three exact evidence quotations. Missing or rejected evidence can produce an explicit insufficient-evidence answer; source validity alone does not guarantee that a quotation answers the question.

03

Data flow: arXiv to searchable evidence

The arxiv_paper_ingestion DAG runs at 06:00 UTC, Monday through Friday, with one active run at a time.

  1. Prepare the runtime.

    setup_environment constructs cached services and proves the database connection before expensive work starts.

  2. Fetch only the approved research scope.

    The arXiv query spans all eight categories. MetadataFetcher enforces the allowlist again before a paper can consume download, parsing, or storage work.

  3. Download and parse defensively.

    PDFs are cached. Docling runs only in Airflow, accepts at most 20 MB and 45 pages, disables OCR and table-structure extraction by default, and records skips or failures instead of losing the whole batch.

  4. Upsert the canonical record.

    PaperRepository.upsert() updates an existing arxiv_id or inserts it. The caller owns commit/rollback, so the repository never hides a transaction boundary.

  5. Analyze failures and rebuild both search projections.

    process_failed_pdfs reports failures. index_to_opensearch rewrites both paper and chunk indices from PostgreSQL so they cannot quietly drift apart.

  6. Publish run accounting and clean temporary files.

    The daily report includes fetched, filtered, parsed, skipped, stored, indexed, embedded, reused, and error counts; cleanup removes old temporary PDFs.

Graceful degradation is intentional. One bad PDF does not stop unrelated papers. An indexing error prevents stale-document deletion and alias movement, preserving the last complete searchable view. A missing index returns an empty result; an unhealthy search backend becomes HTTP 503.

04

Why retrieval has two indices

Paper discovery and evidence retrieval are different ranking problems, so each gets a different document shape.

Alias → concrete index

arxiv-papers → arxiv-papers-v1

One document per paper. Answers “which papers are about this?” using title ×3, abstract ×2, and authors ×1. Every stored paper is searchable even when its PDF could not be parsed.

Alias → concrete index

paper-chunks → paper-chunks-v2

One document per passage. Answers “where does a paper say this?” using content ×3, section title ×2, plus a 768-dimensional vector for semantic similarity.

Chunking policy

Structure first

Docling sections are the natural boundary. Long sections split at paragraph, line, sentence, then word boundaries before a hard cut.

Retrieval-sized windows

Chunks cap at 2,000 characters with 200 characters of overlap. Sections shorter than 100 characters are discarded as parser noise.

Groundable text only

Bibliographies are excluded because they match many titles without grounding a claim. Their text remains in PostgreSQL for future citation work.

splits into two rankings

Papers, best passage firstmaximum 3 passages per paper

Why RRF?

BM25 scores and cosine similarities are not comparable. RRF ignores raw scales and rewards passages both systems rank highly. Hybrid responses label score_kind: "rrf".

What if Ollama is down?

The hybrid route falls back to keyword results and returns mode: "keyword", score_kind: "bm25", and a readable fallback_reason.

Index safety: document IDs are deterministic, unchanged embeddings are reused by content hash, and a full rewrite atomically moves the read alias only when clean. Stale documents are deleted after success. Daily rebuilds are idempotent, self-healing, and friendly to mapping migrations.

How to read a hybrid response

  • hits contains papers, each with at most three ranked passages; it is not a flat list.
  • total is the full BM25 passage match count; fusion reranks a bounded candidate pool.
  • mode says whether semantic retrieval participated. Never infer that from the score.
  • score_kind distinguishes RRF scores near 1/60 from raw BM25 values.
  • matching_passages is truthful for collapsed BM25 results and omitted for bounded hybrid candidates.
  • Categories outside the eight-category corpus return HTTP 422 rather than a misleading empty result.

Representative grounded-answer request

POST /api/v1/ask
Content-Type: application/json

{
  "query": "What model access does Diff Mining need?",
  "top_k": 3,
  "use_hybrid": true
}

The same payload works with /api/v1/stream. Optional model must be configured; categories uses the corpus allowlist. top_k counts paper groups (1–10, default 3), and the query is limited to 500 characters.

06

How grounded answers work

The model selects evidence IDs. The server produces the public answer text.

  1. Retrieve and build context.

    BM25 or hybrid returns grouped passages. Context selects whole passages under a 12,000-character budget, prioritizing initial evidence from up to three papers.

  2. Offer bounded sentence candidates.

    A paper must cover at least 60% of the query terms across its context. Only whole 7–55-word sentences qualify. RAG_SENTENCE_CANDIDATES_PER_PASSAGE=1 remains the default; 2–3 candidates are opt-in because expansion reduced measured relevance.

  3. Constrain and validate the selection.

    Structured output is {"answer":"E1 E3"} or {"answer":"NONE"}. A grammar admits at most three known IDs in increasing numeric order. Independent server validation rejects duplicate JSON keys, unknown/repeated IDs, malformed shapes and excessive selections.

  4. Retry once, then render or reject.

    An invalid selection gets at most one plain-ID retry against the same evidence. Selections are never sorted, deduplicated, truncated or repaired. Valid IDs become exact source quotations with server-owned citation markers, bounded to three excerpts and 200 words.

  5. Buffer before streaming.

    Both endpoints use ordinary Ollama generation and the same validation path. SSE sends source metadata first, then validated quotation deltas and done. Invalid retries emit an error without leaking answer text. Valid abstention uses the explicit insufficient-evidence response.

Attribution and relevance are separate. A correctly quoted source can still be irrelevant to the requested fact. The conservative lexical gate can also reject supported paraphrases or multi-paper questions. These limitations are measured below.

The scope command reports or purges out-of-scope rows. Purge is dry-run by default. A delete requires both --apply and an exact --expected-count, so a stale audit cannot authorize a changed set.

Small glossary

BM25
A lexical ranking algorithm. It is strong when query and document share meaningful terms; field boosts say which matches matter most.
Embedding and KNN
An embedding maps text to a vector. K-nearest-neighbor search retrieves passages close to the query vector, capturing similar meaning despite different wording.
Reciprocal rank fusion (RRF)
Combines ranked lists by position rather than raw score. Here it merges keyword and vector candidates with k = 60.
Index alias
A stable read name such as paper-chunks pointing to a versioned concrete index. Atomic moves enable mapping migrations and rollback.
Retrieval-augmented generation (RAG)
The system retrieves evidence before answering. Here the LLM selects sentence IDs and the server renders exact cited quotations. It does not treat model-written prose as authoritative evidence.
Fact coverage versus attribution
Attribution verifies that a quotation comes from the supplied source. Complete-fact coverage checks whether the selected quotations fully supply requested facts. A response can pass attribution while omitting facts or quoting irrelevant material.
